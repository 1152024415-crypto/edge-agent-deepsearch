Scaling Mobile Agent Systems: From Capability Density to Collective Intelligence

深度整理

研究背景与问题

移动 agent 系统正成为端侧和 AIoT 生态里跑智能应用的关键范式。但它的可扩展性被两件事卡死：一是单设备算力本来就有限，二是不同设备上的智能是碎片化的——每个设备各跑各的 agent，彼此不通信、不协作，算力和知识都用不起来。结果是移动 agent 既做不大（单机能力上不去），也做不强（多机凑不成合力）。这篇要回应的就是「怎么把孤立移动 agent 扩展成一个真正分布式、高效、可扩展的智能系统」。

贡献点

这是一篇研究议程（agenda）论文，贡献在于提出统一的两维度扩展框架。第一维度是单 agent 的能力密度（capability density）：通过紧凑基础模型设计和模型压缩，让单个 agent 在固定算力下能干更多事，把「每比特算力的智能」往上推。第二维度是集体智能（collective intelligence）：通过通信密集的多 agent 协作，让多个设备上的 agent 凑成分布式智能体，把碎片化智能拼成整体。作者把这两条线统一在一个研究愿景下，给移动 agent 的扩展指了路线。

实现方法

作为议程论文，没有给出具体系统实现，但勾勒了技术路线。单 agent 这条线依赖紧凑基础模型设计（更小参数量更高效率的底座）和压缩（量化、剪枝、蒸馏这类手段），把模型塞进端侧受限算力。多 agent 这条线依赖通信密集的协作机制——设备之间通过高效通信协议共享状态、分工任务、聚合结果。两条线在「分布式智能系统」这个目标上汇合：单个 agent 能力密度够高才有余力做通信和协作，集体智能反过来让单个弱 agent 凑成强系统。

实验与结果

未报告具体数据。这篇是愿景/议程论文，没有跑实验、没有 benchmark、没有量化对比。作者基于近期模型和基础设施的进展来论证这两条路线的可行性，但本身不提供实测数据。

对端侧 agent 的意义

这篇对端侧 agent 工程师是路线图层面的参考。它把端侧 agent 的扩展问题拆成「单机能力密度」和「多机集体智能」两条线，比泛泛说「端侧 agent 要扩展」清楚得多。实际工程中，端侧 agent 团队常常纠结是堆单机算力还是做设备协同，这篇给出的框架就是用来理清这个决策的：紧凑模型+压缩是单机侧的硬功夫，多 agent 通信协作是系统侧的软功夫，两边要一起推。对做 AIoT 多设备 agent 协同、边缘集群 agent 框架的团队尤其有方向价值。

局限与未来

第一，议程论文没有实测，两条路线的可行性和代价只能靠近期其他工作背书，本身不证。第二，「通信密集多 agent 协作」在端侧带宽和能耗受限下到底可不可行，作者没讨论通信成本这个硬约束。第三，单作者论文，视角单一，没有给出具体协作协议、压缩方案或评测基准的设计。第四，能力密度和集体智能之间怎么权衡（算力该投单机还是投通信）没量化。未来值得看作者或社区把这个议程落成具体系统，给出端侧多 agent 协同的实测基准。
