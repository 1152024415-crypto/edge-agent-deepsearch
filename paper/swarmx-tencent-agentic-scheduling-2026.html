SwarmX: Agentic Scheduling for Low-Latency Agentic Systems

深度整理

研究背景与问题

Agentic AI 应用把多次模型调用和工具执行串起来跑，给 GPU-CPU 集群的调度出了新难题：推理耗时和模型调用结构往往取决于 prompt 语义，传统调度器看不见这些就压不住尾延迟。云上 agent 服务要低延迟，但请求结构是动态的、跟语义绑定的，老的负载均衡和排队策略直接套不上。这篇就是要给这种语义驱动的 agentic 负载专门做调度。

贡献点

提出 SwarmX，给低延迟 agentic 应用做 agentic 调度的系统。核心创新是用调度专用的神经预测器，把 prompt、设备、runtime、目标模型这几路特征一起吃进去，输出分布式的耗时预测给路由和扩缩容做尾延迟感知决策；还配套了预测器训练和在线自适应机制。新在哪：不是给老调度器打补丁，而是把「语义感知的分布式预测」做成调度底座，再套进一个 scheduler-agent 框架，当通用基底去对接已有调度和模型服务设施。

实现方法

思路是用神经预测器把 agentic 请求的耗时提前估出来，而且是给分布不只是点估，路由和扩缩容就能盯着尾部分位做决策而不是均值。预测器输入四类特征：prompt 语义、目标设备、runtime 状态、目标模型，输出耗时的分布预测。配套有训练流程和在线自适应，让预测器跟着负载漂移自己更新。这些预测器和机制塞进一个 scheduler-agent 框架，作为通用底座去集成已有的调度器和模型服务基础设施，不是另起炉灶替换整套。

实验与结果

两部分评测：一是生产部署，近一千张 GPU 和一百万个 CPU 核；二是 128 张 GPU 测试床的受控实验。覆盖三类工作流：多 agent 代码生成、深度研究、多模态 agentic 流。关键数字：相比当时最强的调度器，尾延迟最多降 61.5%；在相同 SLO 下吞吐最高达到生产调度器的 2 倍。规模和负载都是真实生产级，不是纯模拟。

对端侧 agent 的意义

这篇本身是云端集群调度，但两个思路对端侧有迁移价值。一是「用神经预测器把请求耗时估成分布、按尾部分位做决策」这套，端侧多 agent 或多设备协同时同样面对耗时不确定和尾延迟，分布预测加尾感知的调度逻辑可借鉴。二是 prompt 语义、设备、runtime、目标模型四路特征融合做预测，端侧 agent 异构设备调度也缺这种语义感知的耗时估计。不过端侧资源远小于千卡集群，预测器本身要够轻，直接搬生产版不可行，需裁剪。

局限与未来

调度专用神经预测器自身的推理开销和延迟没在摘要里量化，预测器会不会成为新瓶颈未知。在线自适应怎么避免预测器被脏数据或攻击带偏没展开。只在云端集群验过，端侧或边缘异构场景没测，迁移成本待证。尾延迟降 61.5% 是相对 SOTA 的最好情况，平均收益和最差情况没给。scheduler-agent 框架对接已有设施的具体接入成本和兼容性边界没说清。未来端侧落地要把预测器瘦身，这周没给这条路径。
