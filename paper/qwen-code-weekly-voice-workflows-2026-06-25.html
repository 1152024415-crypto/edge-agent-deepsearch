深度整理

研究背景与问题

Qwen Code 这周的周报。痛点很实在：以前在终端里写 prompt 全靠打字，长命令、复杂参数、中英混排又慢又容易打错；好不容易跑通一个 workflow，跑完就没了，下次想复用得重写一遍，中途断了也接不上；终端 UI 一堆圆角边框堆成墙，思考块没有专门展开键，扩展和 MCP 还得手改配置。这周就是冲着这几个日常难受的点修。

贡献点

这周发了 v0.18.4 到 v0.19.2 五个版本、140 多个 PR，主推三块。一是 /voice 语音输入，按住或点一下说话，转写用 qwen3-asr-flash，快模型顺手清掉口头语和错字。二是 Dynamic Workflows，跑完按 s 存成 slash 命令，断的能在同会话里接着跑。三是 UI 全面瘦身，边框去掉、完成的工具调用折成一行、Alt+T 专管思考块、/extensions 变成交互管理器、MCP 资源能浏览和 @ 补全。另外加了 Artifact 工具把模型输出变成可交互网页、Vision Bridge 让纯文本模型也能看图、/stats 看 token 成本。

实现方法

语音这块分两路：批量模式走 OpenAI 兼容的 chat/completions 加 input_audio 接口，实时模式走 WebSocket 流式 PCM 边说边出字，麦克风采集靠 @qwen-code/audio-capture 这个 N-API addon，Linux 没 addon 自动回退 arecord 或 SoX。转写完快模型只删口头语不改原话，超时就直接用原始转写。Workflow 复用是跑完存到 .qwen/workflows 下成 js 脚本，恢复靠 resumeFromRunId 从 JSONL 日志重放，从最长未变前缀续跑到第一个分叉点。Artifact 全部写本地文件用 file:// 打开，内容必须自包含不许外链 CSS/JS，单页 16MB 上限。

实验与结果

周报没跑 benchmark，只给了工程指标：这周合并 140 多个 PR、跨五个版本号；语音转写支持批量加实时两条路径；workflow 历史跨重启持久化、旧条目自动清理；子 agent 卡死看门狗自动重试 3 次；Artifact 单页上限 16MB。具体延迟、识别准确率、token 节省量都没量化。未报告具体数据。

对端侧 agent 的意义

这周几个点都能往端侧搬。语音输入这条路径最直接：ASR 加快模型清洗的流水线，换上端侧 ASR 和端侧小模型就能在手机或边缘设备上做免打字 agent 交互。Workflow 存盘加断点续跑，端侧 agent 长任务中断恢复是刚需，resumeFromRunId 这套从日志重放、按未变前缀续跑的思路端侧照搬。Artifact 全本地、自包含、走 file://，正好契合端侧不连外网、数据不出端的约束。Vision Bridge 给纯文本模型补视觉，端侧模型多是文本-only，这个桥接思路有用。

局限与未来

全是工程功能堆叠，没有评测证明这些改动真提升了效率或准确率。语音依赖云 ASR，离线场景没说怎么降级。Workflow 复用只在本会话能恢复，跨会话或跨设备没提。Artifact 16MB 上限和自包含约束意味着复杂可视化做不了。Vision Bridge 具体怎么把图喂给文本模型、是不是套了个视觉模型转描述，没讲透。未来端侧落地要把 ASR、快模型、日志重放都换成端侧实现，这周没给这条路径的基准。
