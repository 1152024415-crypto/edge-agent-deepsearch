深度整理

研究背景与问题

现在 AI 正从「问一句答一句」的工具变成能主动干活的 agent，能盯收件箱、整理资讯、跑多步任务。但这些 agent 多数跑在云端，按 token 计费又慢又贵，还把隐私数据送上云。问题是能不能把 agent 跑在自己桌上，既要够快够强，又不能像机房那样吃电。这篇博客正是回答这个本地化痛点。

贡献点

两点。第一，把 NVIDIA DGX Spark 这个个人 AI 超算定位成跑本地 agent 的标准平台，配 GB10 Grace Blackwell Superchip，联发科和英伟达联合设计，单机 1 petaflop FP4 算力，插墙电即跑。第二，串起 OpenClaw、Hermes Agent、NemoClaw 一套本地 agent 生态，从搭助手、自适应学习到行为护栏打通，不止谈硬件，是把本地 agent 全链路铺出来。

实现方法

硬件上 GB10 把联发科的 CPU 性能与功耗控制和英伟达的加速计算合到一颗芯片，桌面机箱插电即用。软件侧 OpenClaw 用来搭和跑 agent，Hermes Agent 在本地长期记忆对话、按用户习惯自我调整，NemoClaw 给 agent 加行为护栏管数据怎么动、连哪些模型。多台 Spark 能并联做推理分摊，手机平板随时查看后台 agent 进度，重活留本地、要弹性再上云。

实验与结果

博客没报告具体 benchmark，只给了几个定性指标：单机最高 1 petaflop FP4 AI 性能，功耗低到能直接插家用墙电，可同时跑多个 agent，多机并联做推理共享。具体的时延、并发数、内存占用都没写。量化数据未报告。

对端侧 agent 的意义

直接面向端侧：DGX Spark 就是「桌面级端侧」，把云端 agent 那套搬回本地。对端侧工程师的用处一是验证「本地 agent 加本地模型」可行，证明插电压得住在桌面跑得动多 agent；二是 OpenClaw、Hermes、NemoClaw 这套框架思路可迁移，记忆、护栏、多机并联的设计给手机或边缘设备做本地 agent 都能借鉴；三是隐私和成本这条路径走通了，端侧落地同样要面对。

局限与未来

没给量化实验，怎么个快法、能并发多少 agent 全靠定性描述。GB10 是高端桌面超算，离真正的手机或 IoT 端侧还差很远，功耗和体积都不是消费级。OpenClaw、Hermes Agent、NemoClaw 是第三方生态，博客没讲联发科自己贡献了多少代码。作者点到了 always-on 智能计算融入日常，但没说怎么从桌面走到手机，隐私也只说本地更安全，没讲本地数据怎么管护。
