Forget to Improve: On-Device LLM-Agent Continual Learning via Budget-Curated Memory

67 开源 2026-06-23 · 学术论文
契合28·厂商5·贡献13·质量13·时效5·开源3
端侧代理记忆管理持续学习安全隐私能耗优化

深度整理

研究背景与问题

端侧 LLM agent 想变聪明靠的不是改权重，而是把经验攒进可检索的记忆里。但这块记忆在端侧有三个硬约束：占 RAM 和电、要靠窄上行带宽跟同伴同步、还因为「agent 读什么就能写什么」变成投毒攻击面。已有工作各管一段：有的记忆无限膨胀不设预算，有的端侧只按成功与否留条目，投毒又被当成纯攻击问题而不是记忆治理问题。这篇就是要用一个统一尺子把这三件事一起管。

贡献点

核心是一个叫 Curator 的机制：给每条记忆算一个「每字节净价值」分数，价值减伤害按字节算，让预算本身当策展人。靠这一把尺子做三个决策：KEEP 在 RAM 和电预算下淘汰低净价值字节；SHARE 只当一条洞察的价值高过上行成本才往外发；TRUST 按来源可信度给同伴传来的条目把关。新在哪：不是各管一段，是一个净价值分数同时管保留、共享、信任三件事。

实现方法

思路是把记忆生命周期全压到一个净价值分数上。每条经验进来先打分：算它能给 agent 带来多少价值、又会造成多少伤害（比如被投毒的风险或陈旧误导），两者相减再除以字节数。KEEP 阶段预算吃紧就按这个分淘汰低价值字节，保住高净价值的。SHARE 阶段一条洞察要不要发给同伴，看净价值是否超过上行带宽成本。TRUST 阶段同伴传来的条目按来源 provenance 设信任门槛。整个过程不碰模型权重，纯靠记忆层治理。

实验与结果

在 LM-agent task-drift benchmark 和一个真实异构 Jetson 测试床（两个机械臂节点加一个 hub）上测的。关键数字：记忆占用降到 2.7 倍，上行带宽降到 2.4 倍，注入攻击成功率从 0.75 压到 0，被投毒或陈旧记忆污染的 case 准确率反而提升。而且这些收益是在不降准确率的前提下拿到的。

对端侧 agent 的意义

这篇几乎就是冲着端侧写的。RAM、电、窄上行、可写记忆被投毒——这四个正是端侧 agent 落地的真痛点。给端侧工程师可直接拿走的：一是净价值每字节这个统一度量，做记忆淘汰和共享决策时不用再分别设阈值；二是 SHARE 那条「价值超过上行成本才发」对带宽抠到极致的边缘协同特别有用；三是 TRUST 按 provenance 把关，端侧 agent 互相传记忆时防投毒有了具体抓手，不是空喊安全。

局限与未来

净价值分数怎么算价值、怎么算伤害，摘要没给出具体公式，可能依赖人工设计或额外模型，落地成本未知。只在 Jetson 加机械臂这个特定测试床验过，手机、IoT 等更受限设备没测。TRUST 按 provenance 把关，但 provenance 本身怎么可信地获取和防伪造没展开。遗忘可能丢掉长期低频但关键的经验，价值函数怎么权衡长短期待解。未来得看价值函数能不能端侧自己学出来。
