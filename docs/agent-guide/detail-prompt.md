# Detail Prompt — 论文详情整理 agent 提示词模板

> 本文给整理 agent 参考。主 agent 起整理 agent 时，必须把本文件全文注入 prompt，不许自写简化版。
> 整理 agent 产出前还必须读 `docs/agent-guide/output-contract.md`（detail 字段契约）和 `docs/agent-guide/research-prompt.md`（理解筛选标准，判断贡献度）。

# 强入口（不许跳过）

1. 先读 `docs/agent-guide/output-contract.md`，确认 detail 字段契约：6 段深度整理，markdown 纯文本，列表页不显示，详情页主体。
2. 再读 `docs/agent-guide/research-prompt.md`，理解论文筛选标准和评分口径。判断「贡献点」和「端侧意义」时要参照这份标准，不能跑偏。
3. 读完后才动手整理。跳过这两份，容易把 detail 写成论文摘要的扩写，失去整理价值。

# 6 段结构（每段写什么 + 不要什么）

详情页主体是 6 段 markdown 纯文本，不重复列表页的 abstract/effects/mechanism，而是更深一层。每段都要有，不能省。

## 1. 研究背景与问题

**写什么**：这篇论文解决什么问题，为什么这个问题重要。一两句话说清痛点，让读者知道「为什么需要这篇」。

**不要**：不堆背景知识，不写「随着大模型发展」这类开场白，不从远古讲起。聚焦这个具体问题为什么值得做。

## 2. 贡献点

**写什么**：核心创新 1 到 3 点，具体说创新在哪。是新的架构、新的记忆机制、新的评测方法，还是对已有方法的改进？说清楚「新在哪」。

**不要**：不写「提出了一个框架」这种泛泛之词。要落到具体：框架里什么组件是新的，比之前方法多了什么。

## 3. 实现方法

**写什么**：技术机制怎么做的。用大白话讲清楚流程：输入是什么，经过哪几步，输出是什么。关键模块怎么衔接，数据怎么流动。

**不要**：不堆术语，不写论文式长句，不贴公式。读者要能看懂「这事大概怎么运转」，不是复现论文。

## 4. 实验与结果

**写什么**：用了什么数据集或测试环境，关键数字是什么。准确率、速度、内存占用、能耗，挑最关键的 2 到 3 个指标写。

**不要**：不罗列全部实验。没有量化数据的写「未报告具体数据」，不许编造或推测。

## 5. 对端侧 agent 的意义

**写什么**：这篇工作和端侧、移动部署有什么关系。是直接面向手机或 IoT，还是方法可迁移到端侧？对落地有什么实际用处？

**不要**：不写「具有重要意义」这类空话。要说清楚：端侧 agent 工程师看这篇，能拿走什么。

## 6. 局限与未来

**写什么**：方法有什么不足，作者自己提了哪些未来方向，你觉得还有什么没解决。

**不要**：不写「未来可期」收尾。要指出具体短板，比如只在模拟器测了、模型还太大、隐私没考虑。

# 硬约束（不可违反）

1. **必须 fetch 论文原文**：arXiv 摘要页、官方页面、论文 PDF，至少 fetch 一个，基于真实内容整理。不许只看标题就编。fetch 失败的，按第 2 条处理。
2. **读不到写明**：fetch 不到原文时，detail 里相应段落写「无法获取原文，基于标题和摘要推断」，不许假装读过。
3. **中文大白话**：不用论文腔，不写「本文提出」「实验表明」「综上所述」。用人话讲，像给同事讲清楚这篇论文。
4. **每段 100 到 200 字，总 600 到 1200 字**：太短没整理价值，太长变论文复述。控制在这个区间。
5. **不用英文双引号**：用「」或不加引号。英文双引号会破坏 JSON 编码，这是踩过的坑。整段 detail 里不许出现 `"` 字符。
6. **6 段都要有**：不能因为某段信息少就省掉。信息少的写「未报告」或「原文未涉及」，但段落标题要在。

# 示例：MemGUI 贡献点段

下面是一段合格的「贡献点」整理，供参照语气和深度：

> 贡献主要有两点。第一，提出了一套面向 GUI agent 的分层记忆机制，把短期操作记忆、中期任务记忆、长期偏好记忆分三层存储，各自有不同的写入和淘汰策略。之前 GUI agent 的工作要么只靠上下文窗口，要么把所有历史塞进一个向量库，没有这种分层。第二，设计了基于屏幕状态变化的记忆触发器，只在界面发生有意义变化时才写入记忆，避免了无操作也记录的冗余。这两点合起来，让 agent 在长程任务里不用带全部历史也能记住关键步骤。

注意这段没有论文腔，没有英文双引号，具体说了「新在哪」，不是「提出了一个框架」。

# 输出格式

整理 agent 输出一个 JSON 数组，每个元素对应一篇论文：

```json
[
  {
    "paper_id": "fresh-edge-agent-paper",
    "detail": "## 研究背景与问题\n\n...\n\n## 贡献点\n\n...\n\n## 实现方法\n\n...\n\n## 实验与结果\n\n...\n\n## 对端侧 agent 的意义\n\n...\n\n## 局限与未来\n\n..."
  }
]
```

- `paper_id`：对应 research run 里的 `id` 字段，必须一致。
- `detail`：6 段 markdown 纯文本，段落用 `## ` 标题分隔，段落间空行。不包含列表页的 abstract/effects/mechanism，是更深一层整理。

主 agent 拿到 JSON 后，逐条 `POST /api/paper-detail` 写入 DB，详情页读取展示。
