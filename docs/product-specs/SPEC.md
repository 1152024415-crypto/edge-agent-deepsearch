# Product Spec

## 产品目标

每周展示端侧 AI Agent 相关最新论文和大厂官方动态。主 agent 通过子 agent 调研得到 10 到 20 条候选内容，校验后发布到服务器，网页刷新展示。

## 用户

- 需要快速跟踪端侧 AI agent 论文的人。
- 需要给论文补洞察人和 wiki 链接的人。
- 使用 Codex/Hermes 等 agent 做周期性调研的人。

## 成功标准

- 主 agent 能把子 agent 的调研结果保存成 `research_runs/*.json`。
- 校验脚本能拦截过期、非论文、字段缺失、链接非法、重复 id。
- 发布脚本能把合格结果发到服务器。
- 服务器页面能刷新展示最新论文。
- 洞察人和 wiki 链接可写。

## 展示字段

页面必须覆盖：

- 论文标题
- 论文摘要
- 论文效果
- 工作原理
- 论文连接
- 洞察人
- wiki连接
- 分数
- 日期
- 关键字标签
- 方向分类：应用 / 框架 / 算法

## 收录规则

- 时间窗口：当前日期过去 7 天。
- 类型：默认收 `source_type: 学术论文`；大厂官方 `官方技术博客` / `官方产品发布` 也可收录。
- 大厂官方约束：非论文条目必须来自官方域名，并设置 `is_major_vendor_official: true`。
- 排序：大厂官方条目无条件排在普通论文前面；同一优先级内再按分数、日期排序。
- 链接：必须是论文原文或权威论文页。
- 效果：必须来自原文；没有则写 `未报告`。
- 数量：目标 10 到 20 篇；不为凑数量收垃圾条目。
- 关键字：每条 1 到 8 个，中文优先，例如 `GUI智能体`、`记忆`、`工具调用`、`端侧部署`、`评测基准`。
- 分类：每条必须归入 `应用` / `框架` / `算法` 一个方向。

## 首页信息架构

- 页面顶部必须有三个 tab：`应用`、`框架`、`算法`，并显示各自数量。
- tab 内排序仍然是：大厂官方优先，然后分数，然后日期。
- 首页面向快速扫读，不写论文式长段落。
- `abstract` 在页面显示为「这是什么」：一句话讲清楚这条内容是什么。
- `effects` 在页面显示为「有什么结果」：只保留关键指标或 `未报告`。
- `mechanism` 在页面显示为「怎么做到的」：用普通中文讲核心方法。
- 深入解释、推导、长引用、人工洞察放 wiki。

## 非目标

- 服务器不搜索论文。
- 不把厂商博客、产品发布、GitHub release 混进论文页。
- 不再把 GitHub Pages 作为最终部署形态。
- 不用旧样例撑页面数量。
