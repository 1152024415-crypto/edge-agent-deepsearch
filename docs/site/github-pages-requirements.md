# GitHub Pages 展示页需求

> 本文只描述当前 GitHub Pages 静态展示阶段要做成什么样。未来服务器版见 `api-contract.md`。

## 目标
做一个高密度、可快速扫描的一周端侧 AI Agent 论文雷达页面。用户打开网页后，应该能在几十篇论文中快速完成三件事：

1. 先看高分论文。
2. 快速判断每篇论文值不值得读。
3. 展开少数论文查看摘要、效果、工作原理，并跳转原文 / wiki。

## 用户
- 主要用户：需要跟踪端侧 AI Agent 论文进展的人。
- 次要用户：调研 agent 的审查者，用页面快速检查 agent 输出质量。

## 页面形态
GitHub Pages 版是静态页面，不做登录、不做真实后端写入。页面应是工具型看板，不做营销页。

### 首屏
首屏包含：

- 标题：端侧 AI Agent 论文雷达
- 更新时间 / 条目数
- 简短状态说明：数据来自 `content/papers/*.md`
- 排序控件：分数、日期
- 筛选控件：推荐意见、厂商、技术分支（如实现成本太高，第一版可先不做筛选）
- 论文列表的前几行

首屏不使用大卡片，不让单篇论文占满一屏。

### 列表
默认展示为高密度表格 / 类表格列表，一行一篇论文。

必备列：

| 列 | 行内展示方式 |
|---|---|
| 分数 | 数字，默认降序 |
| 日期 | YYYY-MM-DD |
| 论文标题 | 一行优先，过长截断，悬停 / 展开看全 |
| 来源 | arXiv / OpenReview / ACL / ACM / IEEE / CVF / PMLR 等 |
| 厂商 / 机构 | 简短 tag |
| 推荐意见 | 纳入 / 待复审 / 排除 |
| 洞察人 | 静态阶段可编辑但仅本地保存 |
| 论文连接 | 打开原文 |
| wiki连接 | 打开 wiki 或待补 |

## 排序与筛选
第一版必须支持：

- 默认按 `score` 降序。
- 点击“分数”切换升 / 降序。
- 点击“日期”切换新 / 旧排序。

后续可加：

- 按厂商筛选。
- 按技术分支筛选。
- 按推荐意见筛选。
- 搜索标题关键词。

## 展开详情
点击论文行展开详情，不跳转新页面。

展开内容：

- 论文摘要
- 论文效果
- 工作原理
- 创新贡献
- 关注建议

展开详情应紧凑，不要把整篇论文分析做成大段长文。长内容可以折叠或限制高度。

## 洞察人与 wiki 链接
GitHub Pages 没有后端，不能真正持久写入仓库。

静态阶段设计：

1. 行内显示 `insight_person` 和 `wiki_url`。
2. 用户可以编辑洞察人 / wiki 链接。
3. 保存时先尝试 `POST /api/insights`。
4. 如果接口不存在，则写入浏览器 `localStorage`。
5. 本地保存的字段必须有明显提示，例如“本地未同步”。

这样未来部署到服务器时，只需要实现 `POST /api/insights`，前端不需要重写交互。

## 数据输入
页面由 `app/build.py` 从 `content/papers/*.md` 生成。

每篇论文最少需要这些字段：

| 字段 | 来源 |
|---|---|
| 论文标题 | frontmatter `title` |
| 论文摘要 | 正文第一段 |
| 论文效果 | `## 实际效果` |
| 工作原理 | `## 工作原理` |
| 论文连接 | frontmatter `url` |
| 洞察人 | frontmatter `insight_person` 或 localStorage |
| wiki连接 | frontmatter `wiki_url` 或 localStorage |
| 分数 | frontmatter `score` |

## 非目标
GitHub Pages 第一版不做：

- 用户系统
- 真实多人协作写入
- 数据库
- 后端搜索
- 评论系统
- 厂商博客 / 产品发布混入论文列表

## 视觉方向
工具型、信息密集、克制。不要做一篇一个大卡片，不要做营销式 hero。

建议风格：

- 桌面端以表格密度为主。
- 移动端以紧凑行卡片为主，但仍保持一屏多篇。
- 字体大小稳定，不使用 viewport 缩放字体。
- 颜色用于区分分数、推荐意见、待复审状态，避免大面积单色主题。

## 验收标准
实现后必须满足：

- 一屏能看到多篇论文行。
- 默认按分数降序。
- 用户能按日期排序。
- 每行能看到标题、分数、日期、论文连接、洞察人、wiki连接。
- 点击行能展开摘要、效果、工作原理。
- 非论文内容不会出现在论文列表。
- `python app/gates/gate_all.py` 通过。
- `python tests/test_build.py` 通过。
