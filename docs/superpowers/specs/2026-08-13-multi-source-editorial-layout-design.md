# 多消息源周报编辑布局设计

## 背景

当前页面已经形成“推荐优先、完整收录在后”的基本结构，但消息量增长到百条后暴露出三个问题：

1. 推荐区采用两列深色卡片，阅读顺序在左右两列之间来回跳，长介绍、标签和理由同时出现时首屏过密。
2. “完整调研”实际剔除了推荐条目，导致来源计数、标签筛选和完整性表述都不准确。当前周实际 114 条，列表只显示 102 条。
3. 正式收录、编辑热点和未经正式审计的 GitHub Trending 共用同一套列表语言，来源变多后读者难以分辨“已核验内容”和“发现线索”。

## 产品原则

- 推荐负责分配注意力，不能代替或删减完整收录。
- 来源是可信度与检索维度，不是首页的主要叙事结构；读者先看本周发生了什么，再按来源核验。
- 真正端侧 Agent 始终按手机、PC、其他端侧、普通推荐排序。
- 正式收录与待核验线索必须在版面和文字上明确分区。
- 百条级列表默认紧凑，复杂筛选渐进展开；所有核心操作支持键盘和可见焦点。

## 采用方案

采用“编辑前台 + 全量资料库”结构。没有采用按来源分频道，是因为同一主题会被拆散；没有采用纯时间流，是因为百条数据里无法快速定位重点。

页面由五层组成：

1. **周报抬头**：显示周区间、总收录、推荐数、真正端侧 Agent 数，并保留周切换和辅助页面入口。
2. **本周优先看**：单向纵向排名清单。每条固定按设备范围/来源/日期/分数 → 中文项目名 → 中文介绍 → 关键词 → 推荐理由 → 英文原标题展示。首屏显示 6 条，可展开其余推荐。
3. **本周判断**：左侧为编辑综述，右侧为外部动态标题与理由；不与正式论文列表混排。
4. **完整资料库**：先展示五档来源的实际收录构成，再提供设备、来源、方向、应用、硬件、模型筛选。完整列表包含所有条目，推荐项在列表中显示推荐标记。
5. **发现线索**：GitHub Trending 独立展示，明确标注“未进入正式收录、需进一步核验”，默认只显示前若干条。

## 视觉方向

采用“中文科技周刊编辑台”而不是终端仪表盘：暖灰纸面、深墨色文字、橙红编辑标记、细分隔线和清晰编号。保留 RADAR 品牌和少量等宽数字，但正文以易读中文无衬线字体为主。

推荐区从整块深色双列卡片改为浅色排名名录。桌面端每行使用三段网格：左侧排名与范围，中间项目名称、介绍和关键词，右侧推荐理由与来源核对信息。读者从上到下阅读，不需要在左右列之间跳转。

完整列表保持高密度，但使用 `content-visibility` 降低百条列表的离屏渲染开销。标签筛选默认仅展示设备、来源和常用方向，其余维度通过“更多筛选”展开。

## 数据与交互

- 推荐区从 `ALL.filter(isRecommended)` 读取，不受完整资料库的搜索和筛选影响。
- 完整资料库从 `ALL` 读取，不再执行 `!isRecommended` 过滤。
- `source_tier` 和 `edge_agent_scope` 作为独立筛选状态；`tags` 继续使用多选集合。
- 来源构成卡片由当前周全部数据动态计数，点击后设置来源筛选并滚动到完整资料库。
- 搜索与排序控件移动到完整资料库内部，避免让读者误以为它们会改写编辑推荐和本周判断。
- 没有数据时显示解释性空状态；加载失败时在资料库内显示重试入口。
- 详情层使用语义按钮和 `role="dialog"`，关闭后把焦点还给触发条目。

## 防回归

1. `tests/test_page_recommendations.py` 锁定五层顺序、推荐字段顺序、设备优先级、完整列表包含推荐、线索区独立和渐进筛选。
2. `app/gates/gate_release.py` 在真实构建产物上检查关键分区存在且顺序正确，并阻止完整列表再次排除推荐项。
3. `docs/site/display-spec.md` 更新为本设计，今后的页面修改必须同时符合该契约。
4. 发布前继续运行 research pipeline、build、gate；部署后以桌面视口检查推荐、来源计数、筛选、详情、周切换、线索展开和控制台错误。

## 验收标准

- 1440px 桌面视口能从上到下连续阅读推荐，不出现双列跳读或文字重叠。
- 当前周完整资料库总数等于 API 中 `papers.length`，来源分档计数之和也等于总数。
- 推荐条目既出现在上方推荐视图，也保留在完整资料库，并带推荐标记。
- GitHub Trending 不再出现在正式来源分档中，页面明确说明其核验状态。
- 设备、来源和标签筛选可以组合，清除筛选后恢复全部条目。
- 页面所有按钮、链接、搜索、周切换、详情关闭均可键盘操作并有可见焦点。
- 页面契约测试、完整测试、静态构建门和线上桌面浏览器验收全部通过后才部署。
