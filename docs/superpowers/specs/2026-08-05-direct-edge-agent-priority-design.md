# 真正端侧 Agent 强制推荐设计

日期：2026-08-05  
状态：已确认（用户确认：关键 Agent 闭环至少部分运行在设备端；手机优先，PC 次之，其他设备完整收录）

## 1. 目标

每周调研继续尽可能广地收录端侧 AI 动态，但把“真正端侧 Agent”从普通端侧推理、量化、缓存、检测和云端 Agent 中可靠地区分出来。凡经主 Agent 阅读来源后确认属于真正端侧 Agent 的条目，必须进入推荐区；推荐区先展示手机端 Agent，再展示 PC 端 Agent，随后展示机器人、车载、IoT 等其他端侧 Agent。

## 2. 判定边界

真正端侧 Agent 同时满足：

1. 工作具有 Agent 闭环能力，至少涉及规划、记忆、工具调用、环境交互或自主行动之一，而非只做一次模型推理。
2. 上述闭环的关键部分实际运行在手机、PC、机器人、汽车、IoT 等终端，或端云协同中由终端承担时延敏感的感知、决策或行动闭环。

以下内容不能认定为真正端侧 Agent：

- 普通端侧模型、量化、剪枝、KV Cache、推理引擎、目标检测或 benchmark；
- 仅标题出现 `agent`、`mobile`、`edge`，正文没有设备端 Agent 闭环；
- 手机或 PC 只是云端 Agent 的入口，核心 Agent 全部运行在云端；
- 只服务于 Agent 训练或集群基础设施、但不在终端运行 Agent 的项目。Microsoft Orchard 属于这一类，可按贡献推荐，但不占用端侧 Agent 强制优先位。

## 3. 数据契约

为每个条目增加两个必填字段：

- `edge_agent_scope`：`待核实` / `手机` / `PC` / `其他端侧` / `非端侧Agent`
- `edge_agent_evidence`：主 Agent 阅读原文后写的简短中文证据，说明哪个 Agent 闭环在什么设备上运行；`手机`、`PC`、`其他端侧`时必填，其余为空。

自动搜集和自动转换只能写 `edge_agent_scope=待核实`，不得根据关键词自动晋升。发布前主 Agent 必须逐条完成分类，校验器禁止发布仍为`待核实`的条目。

`方向:端侧agent`标签收紧为语义标签：只有`手机`、`PC`、`其他端侧`可以使用；这些范围又必须带该标签。这样标签、推荐和证据互相校验，避免旧有宽泛自动标签继续污染推荐区。

## 4. 推荐与排序

机械规则如下：

1. `edge_agent_scope`为`手机`、`PC`或`其他端侧`时，`recommendation`必须为`推荐`。
2. 真正端侧 Agent 的`score_relevance`必须为 8–10。
3. 推荐区排序键依次为：端侧范围优先级（手机、PC、其他端侧、非端侧Agent）、来源层级、总分、日期。
4. 手机、PC、其他端侧 Agent 在卡片上显示清晰的中文范围徽标；普通推荐不显示该徽标。
5. 完整收录区继续保留未推荐条目，检索数量不因推荐规则减少。

## 5. 防回归机制

改动必须同时覆盖：

- 调研 prompt：写清判定正例、反例、设备优先级和逐条核实责任；
- research run 契约与校验器：拦截待核实、漏推荐、低相关分、缺证据和标签不一致；
- 自动汇集脚本：只产出`待核实`，停止自动添加`方向:端侧agent`；
- 存储/API：持久化新字段，兼容旧数据库默认值；
- 页面：使用统一排序键并显示范围徽标；
- release gate：对最终构建产物再次检查所有真正端侧 Agent 均被推荐；
- 测试：覆盖手机/PC/其他端侧正例，以及端侧推理、云端 Agent、Orchard 类基础设施反例。

## 6. 方案比较

### 方案 A：新增经核实的端侧范围字段（采用）

优点是判断有来源证据、可机械校验、可直接表达手机/PC优先级，并且不会把宽泛标签当事实。代价是需要修改契约、存储、页面和历史兼容。

### 方案 B：直接把`方向:端侧agent`当强制推荐标记

改动小，但现有标签由宽泛关键词生成，已经包含大量普通推理和检测条目；继续复用会制造误推荐，也无法表达手机与 PC 的优先级。

### 方案 C：只修改 prompt，由主 Agent 人工记住

速度快，但没有数据和发布门保护，换一个 Agent 或下一周刷新时仍可能复发，不满足“后续避免出现问题”的要求。

## 7. 本轮调研验收

项目修复并通过测试后，按北京时间 2026-07-30 至 2026-08-05 重跑四路检索。验收至少包括：

- 逐条核实并强制推荐真正的手机、PC、其他端侧 Agent；
- 扩展 Microsoft Research 和官方 GitHub 首次公开代码事件，复核 Orchard 漏检；
- Orchard 可作为 Agent 基础设施项目收录或推荐，但标为`非端侧Agent`；
- 构建、校验、部署后打开线上桌面页检查排序、中文内容、链接和控制台错误。
