# 广检索、推荐聚焦设计

## 目标

每周尽可能完整地收集过去 7 天端侧 AI 及其技术栈动态。检索阶段不以“是否值得优先看”为删除标准；所有来源可信、时间有效、主题相关且非重复的内容进入完整收录，主 Agent 再从中策展推荐并排在页面前部。

## 范围边界

- 必收：明确端侧、移动、嵌入式、边缘、NPU/MCU、端侧 Agent，以及量化、KV cache、投机解码、小模型、编译部署、推理框架、端云协同、能耗等端侧技术栈。
- 可收：虽未明确写端侧，但对资源受限部署具有直接迁移价值的高效推理、模型压缩、运行时和 serving 工作；使用低相关分及对应标签，不自动推荐。
- 排除：超出 7 天、完全无关、来源不可信、链接内容不匹配、重复内容，以及只有宽泛关键词碰撞但没有 AI 推理/部署意义的内容。
- 普通量化、剪枝、缓存和 benchmark 不再因“创新一般”直接删除；保留并给较低贡献分。只有完全无关才删除。
- 纯 GUI 操作类 Agent 仍排除，除非含端侧部署、系统、推理优化、安全或硬件方面的有效贡献。

## 数据流

1. 统一模块按运行日计算包含当日的最近 7 个自然日窗口。
2. arXiv、HF Daily Papers、GitHub 大项目和厂商官方来源分别采集候选。
3. 每个来源写入检索覆盖信息；覆盖清单必须证明窗口、逐日/逐来源检查和完成状态。
4. 组装器只硬删除无关、越窗、无来源、重复项，保留低贡献但相关的候选。
5. 自动条目一律为“纳入”，不得产生中文推荐名或推荐理由。
6. 主 Agent 阅读来源后评分、核实归属、中文重写并挑选推荐。
7. 校验与发布门复核覆盖清单、内容契约和推荐契约。

## 检索稳定性

- 时间窗不允许在采集脚本中写死，测试固定日期时通过参数注入。
- arXiv 查询支持分页，不能只取每个查询前 100 条；当页面为空、少于页容量或已经越过窗口下界时停止。
- 厂商使用单一规范清单，至少覆盖设备厂、模型厂和项目要求的模型实验室；人工或浏览器兜底也必须记入覆盖清单。
- HF 覆盖清单必须包含窗口内每个日期。
- GitHub 覆盖清单区分“页面 Trending”和“正式周报大项目 release”，两者不能互相冒充完成。

## 评分与推荐

- 自动评分只能作为待复核初值，不能作为推荐依据。
- 公司归属只能基于作者机构证据，不能因标题或摘要提到 Qwen、Google、NVIDIA 等名称自动判为公司项目。
- 官方来源不等于端侧高相关；相关度仍由内容决定。
- 推荐数量不设比例或上限，由主 Agent按本周实际价值决定。

## 验收

- 固定运行日能得到准确的 7 个自然日窗口。
- arXiv 第二页候选能够进入结果，证明分页生效。
- 普通但相关的量化/serving 工作保留为“纳入”，完全无关内容过滤。
- 四类来源覆盖缺失或日期不完整时，周报组装失败并指出缺口。
- 仅摘要提到厂商模型不会被标为公司项目。
- 所有自动转换条目保持 `recommendation=纳入`。
