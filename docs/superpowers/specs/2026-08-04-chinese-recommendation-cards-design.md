# 中文优先推荐卡与发布防线设计

## 背景与问题

“Agent 本周推荐”已经成为桌面首屏主入口，但当前卡片把英文 `title` 放在最大、最亮的位置，并把 `score_reason` 当成读者说明。实际数据中的 `abstract` 已经是中文，但没有进入推荐卡主层级；27 条推荐里有 25 条 `score_reason` 含 `auto-converted`、`待核实`、`votes=` 或“待后续补”等内部流水线信息。

推荐资格还由 `agent/build_run_week.py` 的标题关键词自动触发。这个机制适合发现候选，不足以代表 Agent 完成阅读后的推荐判断，会把弱相关或未精修条目直接推到首屏。

## 目标

1. 用户扫一眼推荐卡即可读懂“这是什么”和“为什么值得看”。
2. 英文原标题保留用于核对原文，但不再占据视觉主层级。
3. 搜集继续尽可能全；推荐只由主 Agent 精读后产生，不由关键词脚本自动决定。
4. 中文总结或推荐理由不合格时，校验器和静态发布门都必须阻止上线。
5. 本周已有推荐重新审视，弱相关内容回到“完整调研”，保留项补齐中文总结和推荐理由。

## 展示契约

每张推荐卡按以下顺序展示：

1. 排名、来源层级、日期、分数、开源状态。
2. `abstract`：中文一句话结论，作为最大、最亮的主标题；回答“这项工作做了什么”，不能只写研究背景或问题。
3. `recommendation_reason`：中文推荐理由，说明核心价值、结果或方法差异；不重复内部评分证据。
4. `title`：标注“原标题”，缩小并降灰，最多两行。

推荐卡不得展示 `score_reason`。`score_reason` 继续保留在详情和内部校验中，用于评分、机构证据与审计。

历史周数据没有 `recommendation_reason` 时，页面仍显示中文 `abstract` 和原标题，不报错；新发布的当前周推荐必须具备合格理由。

## 数据与流程契约

- 新增可选字段 `recommendation_reason`；当 `recommendation == "推荐"` 时变为必填。
- `abstract` 必须包含足够中文字符，不得是英文原文、空壳或流水线占位语。
- `recommendation_reason` 必须是短中文，不得包含 `auto-converted`、`待核实`、`待后续补`、`votes=`、`精修待补` 等内部标记。
- `agent/build_run_week.py` 生成的全部条目默认 `recommendation="纳入"`、`recommendation_reason=""`。关键词可以继续参与搜集和排序，但不能自动晋升推荐。
- 每周主 Agent 在校验前完成推荐编辑：阅读全文/来源后挑选值得看的条目，重写 `abstract`，填写 `recommendation_reason`，再把 `recommendation` 改为“推荐”。
- 当前周有内容时，发布门要求至少一条合格推荐，避免主 Agent 跳过推荐编辑步骤后静默发布。

## 防复发层级

1. **生成层**：脚本不再自动推荐，避免未经精读的候选进入首屏。
2. **Agent 契约层**：research prompt、output contract、workflow 和 release checklist 明确中文结论与推荐理由是推荐的完成条件。
3. **服务端校验层**：`agent/research_run.py` 拒绝英文/占位摘要，以及缺少中文推荐理由的推荐条目。
4. **静态发布层**：`app/gates/gate_release.py` 直接检查构建后的当前周数据，防止绕过 API 或使用旧构建产物。
5. **页面层**：推荐卡只消费 `abstract`、`recommendation_reason` 和 `title`，不再读取 `score_reason` 作为读者文案。
6. **测试层**：单元测试覆盖英文摘要、占位语、缺推荐理由、脚本自动推荐回归和推荐卡信息层级。

## 数据兼容与存储

`app/storage.py` 新增 `recommendation_reason` 列并为旧 SQLite 自动迁移。API、静态快照和历史周 JSON 原样传递该字段。旧记录字段为空时不影响历史页渲染；只有新 run 经过 validator 时执行推荐必填规则。

## 本周内容修订

- 对现有 27 条“推荐”逐条检查主题与价值，不维持固定数量。
- GUI 自动化、医疗、通用硬件或仅因“量化/蒸馏/边缘”关键词命中的弱相关内容降为“纳入”。
- 保留项依据原论文摘要或官方来源重写中文 `abstract`，填写不夸大的 `recommendation_reason`。
- 原标题保持原文，避免翻译标题造成术语漂移；用户首屏主要阅读中文结论。

## 验收标准

- 桌面首屏 6 张推荐卡的视觉主标题全部为中文结论。
- 每张推荐卡都有中文“值得看”说明；内部流水线词不出现在推荐区。
- 英文原标题只作为次级信息显示。
- 完整调研仍保留全部合格内容，推荐与下方列表不重复。
- 新 run 若含英文摘要、占位语、自动推荐或缺推荐理由，validate/gate 至少一层失败。
- `tests/test_research_pipeline.py`、`tests/test_build.py`、页面契约测试和 `app/gates/gate_all.py` 全部通过。
- 部署后在约 1280×720 桌面视口实测推荐折叠、搜索、详情、周切换、关键链接和浏览器错误日志。
